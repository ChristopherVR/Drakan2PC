# Drakan FMV decoder (native, dependency free C++20)

Decodes the `.VDB` movies of Drakan: The Ancients' Gates (PS2 IPU IDEC intra macroblock streams, see
`docs/reference/fmv.md`) to YUV420 / RGBA8 without FFmpeg. Static library `drakan_fmv`, MSVC and any C++20 compiler.

Licence note: the VLC tables (`src/fmv_tables.inc`, generated by `tools/gen_tables.py` from FFmpeg
`libavcodec/mpeg12data.c`) and the decoding procedure (FFmpeg `ipu_decode_frame`, `mpeg2_decode_block_intra`,
`ff_mpeg1_decode_block_intra`) come from FFmpeg, (c) FFmpeg contributors, LGPL 2.1+. Treat this directory as LGPL 2.1+.

## API (`include/fmv/fmv.h`, namespace `fmv`)

```cpp
fmv::Movie m;                                   // views caller-owned memory
m.open_srsc(hdr342, hdr342_size, blob343, blob343_size);   // bodies of SRSC resources 0x342 / 0x343
//   or m.open_frames(w, h, {{ptr,size}, ...});             // raw frame buffers
m.width(), m.height(), m.frame_count(), m.name();
m.decode_rgba(n, dst, stride_bytes, alpha=255);  // RGBA8, bytes R,G,B,A (alpha 0x80 reproduces the IPU value)
m.decode_yuv(n, yuvframe);                       // fmv::YuvFrame: planes y/cb/cr, MB padded strides
```
Frames are independent intra pictures, so any frame index may be decoded at any time (sequential playback just
reuses buffers). Lower layers: `FrameDecoder::decode(buf,size,w,h,YuvFrame&)`, `Idec` (macroblock engine,
`begin_frame(flags)` / `decode_macroblock(BitReader&, first, MacroblockYuv&)`, `set_intra_matrix`), `BitReader`,
`yuv_to_rgba`, `yuv_mb_to_rgba`. Not thread safe per object; use one `Movie`/`FrameDecoder` per thread.

Implemented grammar: flags byte (DC precision 8-11 bit, DTD dct_type bit with field-DCT interleave, alternate scan,
B.15 intra VLC, q_scale_type non-linear table, MPEG-1 coefficient style incl. its escape forms), mb address
increment / intra / intra+quant, DC differential VLC B.12/B.13, run/level VLC B.14/B.15 (16-bit LUT), 12-bit
escape, MPEG-2 inverse quantisation `(level*qscale*W)>>4` with the default intra matrix (= EE 0x517000),
saturation to [-2048,2047], mismatch control (parity into coefficient 63), float separable IDCT (error < 1 LSB
vs the ideal real IDCT), clamp 0..255, BT.601 limited YCbCr->RGB (8.8 fixed point 298/409/-100/-208/516,
nearest-neighbour chroma as the IPU CSC does). Strict mode checks the frame ends with exactly the 32 bit end marker.

Known deviations / caveats:
* DTD (flag 0x04) field-DCT is implemented per the spec; FFmpeg ignores it. No frame on the disc uses it
  (flags seen: 0x20, 0x22, 0x00), so it is untested against hardware.
* The initial quantiser is code 1 (qscale 2) like the IPU's QSC; FFmpeg sets qscale=1. Irrelevant in practice (MB 0 carries
  an explicit quantiser in all sample frames).
* The CSC coefficients are the textbook BT.601 ones, not verified against real IPU output (PCSX2 `yuv2rgb` uses
  the same BT.601 constants, differences would be <= 1 LSB). Use `yuv_mb_to_rgba` in the single place if a fix is needed.

## Accuracy (tests/fmv_test.cpp vs FFmpeg 2025-10 `ipu` decoder)

| movie | frames | YUV420 PSNR mean / min | max abs sample diff | RGBA PSNR vs ffmpeg swscale (mean / min) |
|---|---|---|---|---|
| INTERFCE id 4 logo 512x512 | 264 (all) | 76.1 / 71.0 dB | 1 | 58.3 / 47.8 dB |
| LEVEL0RO id 6 intro 512x512 | first 300 | 67.8 / 66.4 dB | 1 | 46.5 / 45.4 dB |
| LEVEL0RO id 1 "ez" 320x240 | 195 (all) | 70.7 / 67.9 dB | 1 | 46.7 / 46.4 dB |

All 759 frames parse with zero errors in strict mode. The YUV comparison is the real decoder test (FFmpeg's
simple IDCT differs from ours by at most 1 level). The RGBA numbers are lower only because swscale upsamples chroma with
a different filter; both are well above the 40 dB target. Output frames: `build/fmv/out/*.bmp`; log: `build/fmv/test_report.txt`.

## Speed (this machine, MSVC /O2, SSE2 only, single thread, scalar)

512x512 intro (densest content): 373 fps YUV only, 274 fps with RGBA conversion (3.7 ms/frame).
512x512 logo: 733 / 487 fps. 320x240: 2000 / 1300 fps. Movies play at 25 fps, so a core is ~10% loaded.

```
cmake --build build/fmv/cmake --config Release
# references: tools/pyenv/Scripts/python.exe -I analysis/scripts/vdb_extract.py <vdb> build/fmv/ref/ipu

build/fmv/cmake/Release/fmv_test.exe <file.VDB> <movie id> <max frames> <ref prefix> <out dir> [bmp frame idx...]
```
Env vars for the test: `FMV_VERBOSE=1` prints frames below 40 dB, `FMV_DUMP=file` appends our YUV420 output.
(Note: ffmpeg prints "Invalid data" once per file for the trailing 20 byte end-of-stream chunk; harmless.)

## Integration options

**A. Native replacement (recommended).** Hook the movie player above the hardware (docs/reference/fmv.md section 7 option 3):
when the game starts a Movie, load resources 0x342/0x343 through the runtime's SRSC loader (or mmap the VDB),
`Movie::open_srsc`, then every frame tick (wall clock, fps from the Movie Player object, default 25) call
`decode_rgba(n, texture_map, pitch)` and upload to a host texture; skip 0x1767a0 and call the present hook (0x177650)
semantics yourself (centre w x h on screen). Audio comes from the normal SDB path, not from the VDB.

**B. IPU emulation, EE player keeps running (`include/fmv/ipu_adapter.h`, header only, sketch).** `IpuEmu` models toIPU
FIFO (`feed`), IPU_CMD (`write_cmd`: BCLR/FDEC/IDEC/SETIQ/SETVQ/SETTH), IPU_CTRL flags (`set_ctrl`, (flags&0xfb)<<16),
BUSY and the fromIPU DMA (`drain_out`: 64 qwords = one 16x16 RGB32 macroblock, MB raster order, alpha 0x80). The core
is `ipu_idec_macroblock_rgb32(Idec&, BitReader&, first, uint32_t out[256])`, which produces one macroblock's RGB32
exactly as IDEC does. Decode is macroblock-lazy (driven by fromIPU draining) because the IPU does not know the picture
size; supply it with `set_picture_size` from the 0x342 header. FDEC 0 / TOP peeking, SETIQ payload parsing and
IPU_CTRL.BUSY wiring are left as TODO in the sketch; the game only needs the commands listed in docs/reference/fmv.md section 6.
Pick B only if the recompiled EE code (ring buffers, GS image upload) must stay bit-identical; A is simpler and faster.

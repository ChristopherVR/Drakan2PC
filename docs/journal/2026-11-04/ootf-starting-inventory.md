# OotF starting inventory investigation

A continuation from the fresh, normally completed CD09 corrected-header opening reached the source Atimar actor using ordinary movement. The item did not appear in the inventory UI. This was initially described as a ground pickup failure; that framing was wrong. `parsePcObjects` already translates raw PC link positions into object IDs. A temporary read-only audit incorrectly treated the resulting IDs as indices. The actual source Rynn object1740 links directly to Atimar1059: it is a starting-inventory object. The earlier apparent association with Visibility Toggler2731 came from that audit mistake and is withdrawn. Native disabled world state alone is therefore not a defect.

The actual missing inventory is independently established: all24 native carry cells (player data+0x584 controller, inline cells+0x30,16-byte stride,item pointer+8) are zero in the genuine CD09 quicksave RAM. SaveDocument also finds an empty Rynn carry table in the native Slot33 file. These checks distinguish a missing transfer from absent icons, an unequipped item or a limited UI-state report. Evidence: `build/scratch/ootf-header-fixed/native-inventory-audit.json`, `save-inventory-audit.json`, and continuation RAM/screenshots under `build/scratch/ootf-normal-route/`.

A bounded read-only observer was added to the existing PAL cinematic probe. Enable it with `DRAKAN_STOMP_PROBE=1`, `DRAKAN_ITEM_PROBE=1`; `DRAKAN_ITEM_PROBE_RESOURCE` defaults to `0x344db` (this candidate's Atimar resource). It observes the enabled-bit setter0x17e418, base item initialization0x346180 and melee initialization0x497478. Limits are128 lines and12 samples per function; unrelated classes allocate no observation state. It records entry arguments/callers/flags and only labels a completed native return when the return PC is observed. It changes no guest state.

Canonical executable6A9B068D1F38B383A1B03527455CE9C436B4F9A13478BF36D0CC621F7E9FBCBC compiled and ran this observer against the unchanged CD09 pack and a fresh empty card. `build/scratch/ootf-normal-route/activation-initial/drakan.log` lines912–920 show Atimar enabled by caller0x1ca06c, both item initializers seeing enabled bit1 and registration argument1, then disabled by caller0x451eb4. That caller belongs to0x451d00, a native linked-inventory cleanup routine called by Rynn/NPC/chest initialization. It hides linked type10/11 items and removes their links. This is consistent with the source starting-inventory relationship, not an item-range or collision failure.

The same disabled Atimar state already existed in the earlier class-reference and class-kind candidates before auxiliary header cleanup. Restoring an unrelated native companion is not justified. Original native and converted placed-item flags/initEvents are both1/1; no evidence supports inverting those fields. Model bounds are comparable; the imported/native shading difference remains unproven and has not been patched.

Native Rynn initialization calls this discard path when transient game-state bit0x2 at0x4fbaf8 is set. The source Intro contains no player; the converter supplies a synthetic player with no loadout, while the first playable RV player links Atimar. Whether the synthetic first player consumes the native first-level inventory opportunity is the current hypothesis. The next step is to verify both initialization branches and preserve the actual source loadout through normal native campaign initialization. No item has been inserted into a save, no actor has been force-enabled, and no production behavior fix is claimed yet.

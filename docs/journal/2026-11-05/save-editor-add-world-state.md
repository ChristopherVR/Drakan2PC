# Add Item world-state audit (in progress)

The existing Add Item implementation removes the first untouched level object UID from type 0x24 and removes its UID-to-slot pair from type 0x21. This is real suppression of a world object, not omission of redundant serialization. The historical claim that this was required relied on a failed experiment which appended a record without increasing type 0x21’s total-slot count. That experiment therefore did not isolate retaining all static objects.

Native loader evidence: PAL 16adb8 reads the total-slot count from 0x21 and derives savedCount = totalSlots − staticCount. It allocates saved slots first and then the untouched objects in 0x24 order. Function 16e7c8 restores exactly savedCount records; 16c590 selects type 0x102 record ID slot+1. A sparse appended record does not avoid this layout. The 0x21 UID-to-slot pairs are restored by 18e820. Object references serialized by 16def8 are positional; arbitrary integer scanning of opaque records is not a safe relocation method.

A private preserve-all candidate leaves 0x24 byte-identical, increases the 0x21 total by one, and shifts only UID pair slots at or above the original saved-record count. Its new carried potion uses the existing item body/stream writers. Before native testing, an independent parse confirmed 767 saved records and all original 3,789 static UIDs (the source had 766 saved records), including first UID 5012. The private builder explicitly recompresses changed payloads; an initial builder mistake which changed only decoded data was caught by reparse. Run `save-add-preserve-all4` exercised the existing destructive implementation and is not preserve-all evidence.

Corrected run `build/harness/save-add-preserve-all5` loaded via native Load Game, showed seven actual inventory items including both Health Elixirs, saved through F5 and ended with scripted quit/exit 0. The native save contains 794 records and 3,790 untouched UIDs; every one of the original 3,789 UIDs is still present. UID 5012 is preserved, unlike the destructive control. The actual inventory screenshot was directly inspected. Native save parsing retains the new potion at cell 6 with quantity 100. Private source/card and all previous fixtures remain unchanged. Audit: `build/scratch/save-add-preserve/roundtrip-audit.json`; builder: `build/scratch/save-add-preserve.mts`; native exports remain ignored under `build/scratch/save-add-preserve-decomp`.

A transient watchdog report occurred during loading and execution resumed. This run proves viable table expansion and conservation of original untouched UIDs; it does not establish that every opaque per-class saved reference to an untouched object remains correct. That remaining reference-safety question must be resolved before replacing the production implementation. No production Add Item source/UI change has been made at this checkpoint.

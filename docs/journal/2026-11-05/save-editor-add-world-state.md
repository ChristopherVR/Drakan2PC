# Add Item world-state audit (in progress)

The existing Add Item implementation removes the first untouched level object UID from type 0x24 and removes its UID-to-slot pair from type 0x21. This is real suppression of a world object, not omission of redundant serialization. The historical claim that this was required relied on a failed experiment which appended a record without increasing type 0x21’s total-slot count. That experiment therefore did not isolate retaining all static objects.

Native loader evidence: PAL 16adb8 reads the total-slot count from 0x21 and derives savedCount = totalSlots − staticCount. It allocates saved slots first and then the untouched objects in 0x24 order. Function 16e7c8 restores exactly savedCount records; 16c590 selects type 0x102 record ID slot+1. A sparse appended record does not avoid this layout. The 0x21 UID-to-slot pairs are restored by 18e820. Object references serialized by 16def8 are positional; arbitrary integer scanning of opaque records is not a safe relocation method.

A private preserve-all candidate leaves 0x24 byte-identical, increases the 0x21 total by one, and shifts only UID pair slots at or above the original saved-record count. Its new carried potion uses the existing item body/stream writers. Before native testing, an independent parse confirmed 767 saved records and all original 3,789 static UIDs (the source had 766 saved records), including first UID 5012. The private builder explicitly recompresses changed payloads; an initial builder mistake which changed only decoded data was caught by reparse. Run `save-add-preserve-all4` exercised the existing destructive implementation and is not preserve-all evidence.

Corrected run `build/harness/save-add-preserve-all5` loaded via native Load Game, showed seven actual inventory items including both Health Elixirs, saved through F5 and ended with scripted quit/exit 0. The native save contains 794 records and 3,790 untouched UIDs; every one of the original 3,789 UIDs is still present. UID 5012 is preserved, unlike the destructive control. The actual inventory screenshot was directly inspected. Native save parsing retains the new potion at cell 6 with quantity 100. Private source/card and all previous fixtures remain unchanged. Audit: `build/scratch/save-add-preserve/roundtrip-audit.json`; builder: `build/scratch/save-add-preserve.mts`; native exports remain ignored under `build/scratch/save-add-preserve-decomp`.

A transient watchdog report occurred during loading and execution resumed. This run proves viable table expansion and conservation of original untouched UIDs; it does not establish that every opaque per-class saved reference to an untouched object remains correct. That remaining reference-safety question must be resolved before replacing the production implementation. No production Add Item source/UI change has been made at this checkpoint.

## Original-save counterexample and native observer checkpoint

The bounded default-off PAL observer was compiled in executable SHA256 `466227D10103FF8B19450FAEFDA6A724FEABA70960C502AC6E0E457F45E6516B` and run from an immutable private copy. `build/harness/save-add-original-refprobe` loaded the untouched six-item source through native menus, showed its inventory, saved through F5 and ended with scripted quit/exit 0. The opt-in observer emitted actual static-range resolution calls while saved records were being restored. For example, saved record 690 resolved static slots 4228, 4229 and 4230; record 691 resolved 4129 and 4228–4230; record 705 resolved slot 828. The saved/static boundary was 766 and the total was 4555. These are original-save observations, not artifacts of a modified candidate. The separate 32-line non-record budget captured ordinary UID-map lookups without exhausting the saved-record budget.

The trace contains 666 distinct saved-record/static-target observations across 133 source record IDs, in addition to 32 non-record details. Immediate caller 16dee8 is the shared resolver wrapper, not the ultimate class serializer. Completed-load summary output was not observed, so this checkpoint relies on the emitted entry observations and native run outcome rather than inferring completion from yielded calls. Subsequent diagnostic work will identify the class helper and serialized byte offsets.

Independent native analysis also rules out assuming the saved-record set is reference-closed: 1684b0 makes one classifier traversal and appends untouched objects afterward; 168b08 does not implement a general inbound-reference closure pass. Shared reference writer 189978 writes a four-byte positional slot, and inverse 189a50 resolves that slot before rebuilding the runtime handle. Common object handle lists and object-group parent/member references use this path. Therefore merely shifting the 0x21 UID pairs, even with the successful preserve-all/F5 experiment, does not establish safe general insertion.

The four counted slot arrays following the 0x21 UID pairs also require typed relocation when they target static slots. Their source lengths here are 13, 24, 14 and 70; all their actual values are below 766, so that particular omission did not affect the private sample. The separate trailing manager bytes are not a generic integer array and must remain untouched. Production Add Item remains unchanged pending typed-reference relocation; its current world-object suppression is still a material limitation.

## Native reference offsets

The observer now unwraps the verified PAL resolver frames to report the class/common restore caller. It observes the compressed stream's actual cursor (`total_out - buffered bytes remaining`) before a successful four-byte read. Counting only calls to 4a1650 was rejected: string and skip helpers can consume bytes directly through 4a2ed0, producing inaccurate accumulated offsets. The earlier `save-add-offset-refprobe` run is not accepted offset evidence.

Canonical executable SHA256 `73898E34BCBA1FA710D783E1118FB4574B64E52E6F86F93E5522A536B63C1EE1`, retained under `build/scratch/save-add-preserve/play-offset`, passes native load, inventory, F5 and scripted quit/exit 0 in `save-add-cursor-refprobe`. Independent parsing of the untouched source verifies all 670 reported numeric offsets contain exactly the observed four-byte target slot. Two additional observations explicitly report unknown offsets (record 218/slot 1702 and record 334/slot 3866); they are not guessed or used for relocation. Uncompressed-stream offsets are also deliberately unknown. Audit: `build/scratch/save-add-preserve/cursor-audit.json`.

The 672 observations comprise 632 common object-list references (restore caller 179660), 33 from 3e2b5c, three from 40e1e0 and one each from 2d9358, 2b0df0, 3ab9e0 and 3abb18. These identify further typed layouts to investigate. They do not authorize blindly changing matching numbers elsewhere, prove general coverage across classes/saves, or complete the production Add Item repair.
